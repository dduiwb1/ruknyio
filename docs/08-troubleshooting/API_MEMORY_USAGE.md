# استهلاك ذاكرة الـ API (5GB+)

## الأسباب المحتملة

1. **Node.js / V8**
   - بدون تحديد حد، V8 يسمح للـ heap بالنمو (غالباً 2–4 GB+ على 64-bit).
   - في وضع التطوير (`nest start --watch`) يبقى الكومبايلر والكاش في الذاكرة.

2. **Prisma Client**
   - الـ schema كبير (عدد كبير من الـ models) فيولد Prisma Client ثقيل في الذاكرة (عشرات الـ MB أو أكثر).

3. **وضع التطوير (--watch)**
   - كومبايلر TypeScript (ts-node أو SWC) يحتفظ بـ AST وكود مُترجم في الذاكرة.
   - إعادة تحميل الملفات تزيد من استهلاك الذاكرة مع الوقت إذا لم يُجمّع الغarbage.

4. **تسجيل استعلامات Prisma (query logging)**
   - `emit: 'event', level: 'query'` يخزّن نصوص الاستعلامات في الذاكرة عند كثرة الطلبات.

5. **مكتبات ثقيلة تُحمّل عند البدء**
   - sharp، pdfkit، googleapis، socket.io، وغيرها تُحمّل كلها مع تشغيل التطبيق.

## ما يمكنك فعله

### 1. تحديد حد لـ heap في التطوير (مُوصى به)

قبل تشغيل الـ API اضبط المتغير ثم شغّل السكربت العادي:

**PowerShell:**
```powershell
$env:NODE_OPTIONS="--max-old-space-size=2048"
npm run start:dev
```

**Cmd:**
```cmd
set NODE_OPTIONS=--max-old-space-size=2048
npm run start:dev
```

أو استخدم السكربت الذي يحدّ الـ heap (يحتاج `npm install` مرة واحدة لـ cross-env):
```bash
npm run start:dev:lowmem
```
(يضبط حد الـ heap إلى 2GB تلقائياً على Windows و Linux.)

(2048 = 2GB؛ يمكنك تخفيضها إلى 1536 إذا كفى التطبيق.)

### 2. تقليل تسجيل استعلامات Prisma في التطوير

في `prisma.service.ts` يمكن تعطيل تسجيل كل استعلام في التطوير وترك التحذيرات فقط، أو تفعيل التسجيل فقط عند الحاجة (مثلاً عبر متغير بيئة) حتى لا تتراكم نصوص الاستعلامات في الذاكرة.

### 3. تشغيل الإنتاج محلياً للاختبار

تشغيل البناء العادي ثم تشغيل الملف المُترجم يقلل استهلاك الذاكرة مقارنة بـ `start:dev`:

```bash
npm run build
npm run start:prod
```

## ملخص

| السبب              | التأثير التقريبي | الحل                          |
|--------------------|-------------------|-------------------------------|
| V8 heap بدون حد   | عالي              | `NODE_OPTIONS=--max-old-space-size=2048` |
| وضع --watch       | متوسط–عالي       | استخدام `start:prod` عند عدم الحاجة لـ watch |
| Prisma Client كبير| متوسط             | مقبول؛ تحديد الـ heap يحدّ المجموع |
| Query logging     | منخفض–متوسط      | تقليل أو تعطيل في التطوير   |

بعد تحديد `--max-old-space-size=2048` (أو 1536) يُفترض أن يستقر استهلاك الذاكرة حول 2GB أو أقل في التطوير.
