# استكشاف: POST /api/auth/refresh 401 و hasCookies: false

## ماذا يظهر في السجل؟

```
[Auth Proxy] Refresh request: { hasCookies: false, cookieNames: [] }
[Auth Proxy] Refresh response: { status: 401, hasSetCookie: true }
POST /api/auth/refresh 401
```

## التفسير

### 1. لماذا `hasCookies: false`؟

الطلب الواصل إلى **Auth Proxy** (Route Handler) لا يحتوي على هيدر `Cookie`. أي أن المتصفح (أو العميل) لم يُرسل أي كوكيز مع طلب `/api/auth/refresh`.

يحدث هذا عادة في حالتين:

| الحالة | التفسير |
|--------|---------|
| **المستخدم غير مسجل الدخول** | زيارة `/login` أو أي صفحة بدون وجود جلسة. الـ AuthProvider يحاول `refreshToken()` للتحقق من وجود refresh في الكوكي. لا توجد كوكيز → الطلب يصل بدون Cookie → 401 متوقع. |
| **انتهت الجلسة أو تم مسح الكوكيز** | المستخدم كان مسجلاً ثم انتهت الصلاحية أو مسح الكوكيز. عند أي 401 التطبيق يحاول refresh، والطلب يصل بدون كوكي → 401. |

في كلا الحالتين **401 من `/api/auth/refresh` متوقع** عندما لا يُرسل refresh token.

### 2. هل الكوكيز تُرسل من المتصفح؟

نعم. في الكود:

- طلبات `/api/auth/refresh` تُرسل عبر `fetch(..., { credentials: 'include' })`.
- نفس المنشأ (مثلاً `localhost:3000`) → المتصفح يرفق الكوكيز تلقائياً مع الطلب عند وجودها.

لذلك:

- إذا كان المستخدم **لم يسجل الدخول** أو **لا يملك كوكيز صالحة** → الطلب يصل بدون Cookie → `hasCookies: false` و 401 طبيعيان.
- إذا كان المستخدم **مسجلاً** والكوكيز موجودة → الطلب يجب أن يصل مع Cookie؛ إن استمر `hasCookies: false` فهناك مشكلة (نطاق/مسار الكوكي، أو الطلب من سياق لا يرسل كوكيز).

### 3. أخطاء Turbopack (FATAL)

الرسائل من نوع:

```text
FATAL: An unexpected Turbopack error occurred. A panic log has been written to ...
```

هذه أخطاء من **Turbopack** (محرك التطوير في Next.js)، وليست من منطق المصادقة.

**ما يمكن فعله:**

- تحديث Next.js إلى آخر إصدار.
- تشغيل التطبيق **بدون Turbopack** للتأكد من أن السلوك لا يتغير:
  - إزالة `--turbo` من سكربت التشغيل إن وُجد، أو
  - استخدام إعدادات Next التي لا تفعّل Turbopack افتراضياً.

### 4. طلبات 404 (أيقونات وملفات)

مثل:

- `GET /icons/icon-72x72.png 404`
- `GET /icons/icon-144x144.png 404`
- `GET /screenshots/dashboard.png 404`

معناها أن هذه الملفات غير موجودة في `public/` أو المسار المستخدم. الحل: إضافة الملفات في المسارات الصحيحة أو إزالة/تصحيح الإشارات إليها (مثلاً في الـ manifest أو الروابط).

## الخلاصة

| الظاهرة | السبب المحتمل | الإجراء |
|---------|----------------|---------|
| `hasCookies: false` + 401 على `/api/auth/refresh` | لا توجد جلسة (غير مسجل أو انتهت الجلسة) | سلوك متوقع؛ لا حاجة لتعديل إذا كان المستخدم فعلاً غير مسجل. |
| نفس المشكلة مع مستخدم مسجل يتوقع البقاء داخل التطبيق | الكوكيز لا تُرسل أو انتهت صلاحيتها | مراجعة إعدادات الكوكي (path, domain, SameSite) وضمان أن الطلب من نفس المنشأ وبـ `credentials: 'include'`. |
| FATAL Turbopack | خطأ في Turbopack | تحديث Next.js أو تشغيل المشروع بدون Turbopack. |
| 404 لأيقونات/صور | ملفات مفقودة | إضافة الملفات أو تصحيح المسارات. |
